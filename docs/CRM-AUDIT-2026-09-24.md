| Mechanic | Where | Effect |
|---|---|---|

| Explicit cases run first and RETURN | `crm_engine.go:779-807` | `order.delivered` with `offer_pack>0` -> `crmOnPackDelivered` (W-02/W-05) and returns; `wallet.recharge_settled` -> `crmOnRechargeSettled` (W-04) and returns; `offer.finalized` -> W-01 then falls through; `waitlist.joined` -> no-op then falls through. |
| Known condition keys | `crm_router.go:125-168` | Only `order.is_promotional_only`, `product_line`, `orders_count`, `complaint.type`, `new_eta_known`, `rating`. Any other key -> error -> fail closed (logged once per process per (trigger,error), `crm_router.go:92-99`; NO dispatch row is written). |
| Condition grammar | `crm_router.go:180-217` | `||`, `&&`, `(` are unparsable -> fail closed. |
| Day claim | `crm_engine.go:577-590`, unique index `crm_offers.go:242` | `crmDispatchAt` claims `(trigger_id, consumer_id, ist_day)` BEFORE guards; a lost claim returns `("","")` with no row and no log. |

| Caps | `crm_engine.go:655-669` | `crmCapLimit` reads only `per_offer`, `per_customer`, `max_total`. `per_order`, `per_complaint`, `per_event`, `per_quarter`, `per_cycle`, `max_calls`, `window_days` are ignored (B-01's 7-day cycle is hand-coded at `crm_engine.go:970`). |

| Transports today | `crm_channels.go:260-275`, `crm_push.go:47-59`; HANDOFF §5 (env as of 2026-09-20, not re-verified against Render here) | inbox always; SMS needs `CRM_MSG91_AUTHKEY` + `CRM_DLT_TEMPLATE_IDS[trigger]` (mapped for W-01, W-07 only) and category != promotional (`crm_channels.go:395-397`); WhatsApp needs `CRM_WA_TOKEN`+`CRM_WA_PHONE_ID`+`CRM_WA_TEMPLATE_NAMES[trigger]` (none set); push needs `EXPO_PUSH_ENABLED=true` AND a token in `consumer_push_devices` (the app has no `extra.eas.projectId` in `app.json`, so no device has ever minted a token); rcs / ai_call / human_call / email / admin_console are not transports (`crm_channels.go:86-89`). |
| Scheduled runner | `crm_engine.go:812-892` | Hand-coded: W-03a, W-03b, W-06, W-07 (per live offer), B-01 (09:00), B-02 (12:00), W-10 (18:00). No generic cron; every other `kind:"scheduled"` trigger has no runner. |

## 4. Structural gaps (proven)

1. Per-day claim loses the second event of the day. `crmDispatchAt` (`crm_engine.go:577-590`) claims `(trigger_id, consumer_id, ist_day)` before the guards and returns `("","")` on a lost claim with no dispatch row and no log line. Every per_order / per_complaint / per_event trigger (D-01, D-02, D-06, A-02, E-01, E-02, E-04, E-06) therefore fires at most once per consumer per IST day: a household with the morning subscription drop and an afternoon instant order gets one confirmation and one "Delivered"; a second complaint the same day is never acknowledged. Because the claim precedes the guards, a SUPPRESSED row (G8 dedup, G9 inbox error) also burns the day. Fix: key the claim on the event (`order_id` / `complaint_id`) for per_order/per_complaint triggers, and write a row (or at least a log) when the claim is lost.
2. Delay is ignored everywhere. `crmTrigger` has no `Delay` field (`crm_engine.go:60-78`); `crm_router.go:36-38` documents it; the worker drains events on the next tick. Affects A-01 (PT2H), A-05 (PT2H), C-03 (PT1H), C-07 (PT2H/PT12H), E-07 (PT4H), E-02 `sla_acknowledge`. Fallback `after`/`at`/`if` are parsed and ignored (`crm_channels.go:97-100`): a fallback fires immediately on unavailability, so "sms after PT4H if not_read" (W-07) is really "sms now because WhatsApp is nil". Fix: honour `delay` by scheduling `not_before` on the outbox row (`crmEvent`) and skipping rows whose time has not come.
3. Complaint enum mismatch. App sends `missing | quality | late | payment | rider | app | other` (`lib/complaints.ts:41-48`), backend accepts exactly that set and maps typos to `other` (`complaints.go:36-39`, `:117-120`). Triggers expect `wrong_item | damaged | missing` (E-04), `quality_safety` (E-05, F-06). Only `missing` overlaps. Proposed map: `quality` -> E-05, `missing` -> E-04, `late` -> E-03, everything -> E-02.
4. E-05 (milk safety) is fully dead: template null (filtered at `crm_router.go:47`), value `quality_safety` never sent, `human_call` not a transport, no on-call paging, no G7 hold, its sms fallback has no body. A quality complaint gets "we'll fix within 24 hours".
5. W-03b consent gating: the G2 row (`kind: promotional`) is derived only from app-side `marketing_*` toggles (`consents.go:243-320`); TTL 7 days from the grant (`crm_engine.go:376-388`). Promoter-enrolled households who never grant in the app are suppressed every day; SMS refuses promotional outright (`crm_channels.go:395-397`); WhatsApp has no keys. Net: W-03b reaches the inbox only for app users who ticked a marketing box within the last 7 days. The HANDOFF's "unresolved" question is answered: `recomputePromoConsent` DOES write the row, but only when marketing consents are posted.
6. `crm_tokens_test.go` blind spots: (a) it checks token resolvability only, never conditions - E-07 (unknown keys) and E-04 (enum) are asserted "reachable"; W-02/W-05 are asserted reachable via the generic router although they are reached only by the explicit pack path and fail closed in the generic one; (b) its sample payloads are hand-written, so the real `order.dispatched` payload's missing `promotional_only` (D-02 dead) is invisible; (c) it hands an order with `Total 70` to `crmEventParams` for every topic, so the E-04 refusal on an order-less complaint is invisible; (d) it `continue`s silently on every dead topic (32 dead triggers pass); (e) it never touches `delay`, `frequency_cap` keys, or the conditional template of B-06; (f) it excludes template-less triggers, hiding that the safety trigger is unroutable. `crm_router_test.go` never dispatches an instant order, so D-02's fail-closed path is untested.
7. D-02 never fires (new finding): `order.dispatched` payload lacks `promotional_only` (`delivery_svc.go:932-935`) and the second condition fails closed (`crm_router.go:128-132`). The only warning is once per process (`crmCondFailClosed`), and no dispatch row is written, so the operator log shows a trigger that is quiet, not broken.
8. B-06's conditional template is unsupported: `crmTemplateRef.String()` returns the `then` branch only (`crm_engine.go:113-118`), so the `if` is never evaluated.
9. Condition grammar: `||`, `&&`, `(` fail closed (`crm_router.go:186`); no generic scheduled runner exists (`crm_engine.go:812-892` hand-codes W-*, B-01, B-02, W-10), so 20 of the 27 scheduled/ai triggers have no runner at all.

G5 service avoid-window (22:00-07:00) is not enforced (`crm_engine.go:310-341` only gates promotional): subscription D-01 lands at 00:00-00:15 IST after the midnight lock; with Expo push enabled it would wake the handset at midnight (`crmPushPriority` high, `crm_push.go:121-126`).
